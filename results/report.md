## 一、先读这段：哪些数字有效，哪些没有

本次运行用的是 `mock` 提供方 —— 它不是模型，而是一段**确定性规则脚本**。因此：

| 数字 | 在 mock 下是否有效 | 为什么 |
|---|---|---|
| 调用次数 / token / 成本 | ✅ 有效 | prompt 是管线真实拼出来的，token 计数基于真实文本 |
| 契约合规率 / 重试次数 / 熔断 | ✅ 有效 | 这是管线机制，与生成内容的模型无关 |
| 故障注入下的拦截率 | ✅ 有效 | 坏输出由脚本精确注入，可复现 |
| 无依据断言率 / 约束覆盖率 | ⚠️ 反映脚本设定 | mock 的产出由写死的规则决定，不是模型行为 |
| 追问命中率 | ⚠️ 自证 | mock 的判定规则与用例标注共用同一套关键词，必然一致 |
| 延迟 | ❌ 无意义 | mock 不产生真实网络与推理耗时 |

**结论：这份报告能证明「管线机制是通的、账是算得清的」，不能证明「某个模型有多强」。** 要得到后者，请用真实模型重跑（见文末命令）。

| 伪造引用（偶发：只坏第一次） | `multi` | 6 | 6（100%） | 0（0%） | 2.0 |

| 输出不是合法 JSON（偶发） | `evidence-once` | 6 | 0（0%） | 0（0%） | 1.0 |
| 输出不是合法 JSON（偶发） | `multi` | 6 | 0（0%） | 0（0%） | 1.0 |

这三种故障分别考验管线里的**不同那一层**，所以三行的结论完全不同：

- **伪造引用（偶发：只坏第一次）** —— 写作环节凭空造了一条指向不存在证据的断言。偶发故障，重试/退回有救。
- **忽略客户约束（持续：一直坏）** —— 写作环节始终不回应客户约束。持续故障，退回了也改不动 —— 审校不是万能的。
- **输出不是合法 JSON（偶发）** —— 最基础的契约失败，靠本地重试吸收。

## 六、结论

- **给证据比不给证据重要得多。** 不检索时无依据断言率 100%（42/42 条）；检索一次之后降到 0%（0/42 条），而调用次数一次都没多（都是 1.7 次），只是提示词变长了。
- **多智能体的开销是实打实的。** 同样一批用例，`multi` 平均 4585 tokens/次，`evidence-once` 是 1499，倍率 **3.1×**（平均调用 4.5 次 vs 1.7 次）。
- **在正常路径上，多出来的开销没有换来质量提升。** 两条流水线的无依据断言率相同（都是 0）—— 这条结论和 Anthropic / Cognition 的工程复盘一致：编排本身不产生正确性，它只在**故障路径**上产生价值。
- **审校的价值体现在故障路径上。** 注入同样的坏输出：没有审校的流水线有 **12/18** 次把问题带进了最终产物；有审校的是 **6/18** 次。
- **审校不是万能的。** 对「一直坏」的模型，问题最终**都**留在了产物里（`evidence-once` 6/6，`multi` 6/6）——审校能发现并退回，但改不动一个持续失效的写作环节。**这种情况下正确的动作是停下来找人或者换模型，而不是让它再试一次。**

## 七、怎么复现

```bash
# 离线复现（零依赖、不花钱）
python -m arksol eval --provider mock --out results/

# 用真实模型重跑（需要自己准备 key，只走环境变量）
export ARK_API_KEY=...
export ARK_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
export ARK_MODEL=doubao-seed-2-1-turbo-260628
export ARK_PRICE_IN=3 ARK_PRICE_OUT=15   # 元/百万 tokens，用于成本换算
python -m arksol eval --provider openai-compat --out results/ark/
```

逐条明细见同目录 `results.csv`；原始记录见 `raw.json`；每一步的 trace 见 `traces/`（JSONL，可用 `arksol.trace.read_trace` 读回）。
